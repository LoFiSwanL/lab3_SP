# Захист лабораторної №3

## Демонстрація

1. Відкрити `examples/factorial.c`: змінні, цикл, умова, повернення результату.
2. Виконати `make`, потім `make demo`. Пояснити результат 120 в обох реалізаціях.
3. Відкрити `build/ast.html`, натиснути «Вмістити», згорнути й розгорнути `While`.
4. Показати `src/lexer.l`, `src/parser.y`, функції `evaluate`, `execute_statement`
   та `generate_python` у `src/ast.c`.
5. Відкрити `build/result.py`: цикл і умова з AST стали операторами Python.
6. Запустити приклади синтаксичної помилки й ділення на нуль із README.
7. Виконати `make test` і відповісти на наведені нижче питання.

Для відеозахисту потрібно самостійно записати екран, камеру та голос,
завантажити відео на YouTube й додати посилання разом із GitHub у клас.
Альтернатива за умовою — особистий захист на парі.

## Теорія

**Чим відрізняються Lex/Flex і YACC/Bison?**
Flex генерує лексер із регулярних виразів: послідовність символів стає токенами.
Bison — аналог YACC, який генерує синтаксичний аналізатор із контекстно-вільної
граматики. Він перевіряє структуру послідовності токенів. У цьому проєкті
використано стандартний режим Bison — LALR(1).

**Як обирається правило Flex?**
За найдовшим збігом; за однакової довжини перемагає раніше записане правило.
Тому `if` є ключовим словом, а `iffy` — одним ідентифікатором.

**Що таке LALR(1)?**
Look-Ahead LR: розбір зліва направо, побудова правостороннього виводу у
зворотному порядку, один токен випередження. Стани LR(1) з однаковими LR(0)
ядрами об'єднують, об'єднуючи множини випередження. Це зменшує таблиці,
але може створювати конфлікти для деяких граматик, придатних для LR(1).

**Як працює аналізатор?**
Він зберігає стек станів і семантичних значень. За поточним станом та токеном
таблиця ACTION визначає дію: shift, reduce, accept або error. Shift переносить
токен у стек; reduce замінює праву частину правила його лівою частиною,
виконує семантичну дію й використовує GOTO для наступного стану.
Наприклад, для `2+3*4` спочатку формується вузол множення `3*4`, потім додавання.

**Що таке shift/reduce-конфлікт?**
Для того самого стану й токена можливі і shift, і reduce. Наприклад, після
`2+3` перед `*` без пріоритетів незрозуміло, чи згортати додавання.
У `parser.y` пізніше оголошений рівень має вищий пріоритет: `* / %` вищі за `+ -`.
Пріоритет правила зазвичай береться з його останнього термінала, `%prec` його
перевизначає. Вищий пріоритет токена дає shift; правила — reduce. За однакових
пріоритетів `%left` дає reduce, `%right` — shift, `%nonassoc` забороняє ланцюжок.
Якщо пріоритетів недостатньо, YACC/Bison за замовчуванням обирає shift і попереджає.

**Як розв'язано «висячий else»?**
У `if(a) if(b) s1; else s2;` гілка `else` належить найближчому незавершеному `if`.
Правило без `else` отримує `%prec IF_WITHOUT_ELSE`. Токен `ELSE` має вищий
пріоритет, тому аналізатор робить shift. Це свідоме розв'язання неоднозначності.

**Що таке reduce/reduce-конфлікт?**
Можна згорнути за двома різними правилами. Bison за замовчуванням обирає раніше
записане, але покладатися на це небезпечно: можуть виконатись різні семантичні дії.
Потрібно прибрати дублювання або неоднозначні порожні правила й переробити граматику.

**Де побачити конфлікти?**
Bison повідомляє про нерозв'язані конфлікти під час збірки. У `build/parser.output`
є стани автомата; параметр `--report=state,solved` також показує розв'язання
конфліктів пріоритетами. У нашій граматиці нерозв'язаних конфліктів немає.

## Питання по коду

**Що означають `$$`, `$1`, `$3`, `@1.first_line`?**
`$$` — семантичне значення лівої частини правила; `$1`, `$3` — значення символів
праворуч. `@1.first_line` — номер рядка першого символу. Наприклад, дія
`expression '+' expression` створює `Binary` з лівим `$1` і правим `$3` нащадками.

**Що таке AST і чим воно відрізняється від дерева виводу?**
AST зберігає змістовні вузли: операції, числа, змінні, оператори. У ньому немає
службових дужок, крапок з комою та проміжних нетерміналів. Пріоритет уже
виражений структурою нащадків. `a/b/c` у `Node` — нащадки, `next` — наступний
оператор у списку блоку. Для `If`: `a` — умова, `b` — then, `c` — else.

**Де семантика?**
`evaluate` обчислює вирази, `execute_statement` виконує оператори. Контекст містить
області видимості, результат і прапорець `return`. Нова область створюється
для кожного блоку. Пошук змінної йде від внутрішньої області до зовнішніх.
Помилки неініціалізованих/неоголошених змінних перевіряються під час виконання,
тому це не повний статичний аналізатор C.

**Навіщо у Python окремий runtime?**
Python має необмежені цілі числа, інші правила від'ємного ділення і немає областей
видимості для `if`/`while`. Runtime відтворює наші 32-бітні `int`, ділення до нуля,
області блоків і перевірки. Імена C зберігаються в словниках, тому навіть
ідентифікатор `class`, допустимий у C, не псує згенерований Python.

**Це справді генерація коду?**
Так. Генератор обходить AST і записує окрему Python-програму з операторами
`while`, `if`, `return` та викликами runtime. Вона запускається Python без
повторного запуску лексера, Bison або C-інтерпретатора.

**Як побудовано візуалізацію?**
AST серіалізується в JSON усередині HTML. JavaScript рекурсивно розміщує
нащадків нижче батьків і створює SVG-вузли та ребра. Згортання змінює видиму
частину дерева; JSON відповідає саме розібраній програмі.
